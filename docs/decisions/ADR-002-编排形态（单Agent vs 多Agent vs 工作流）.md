# ADR-002：编排形态（单 Agent vs 多 Agent vs 普通工作流）

## Status

Accepted（Phase 1）

## Background

题目显式要求「可以使用单 Agent、多 Agent 或普通工作流，请简单说明选择原因」，这段选择必须能在面试中讲清。核心约束来自题目第 5 条：发现总额不一致、字段缺失、日期异常或重复申请时「**不要自行猜测**，应标记并提醒人工确认」。本 ADR 论证编排形态的选型。

## Decision

采用「**普通工作流（确定性管线）+ 可选 LLM 单点旁路**」。既不是单体 Agent，也不是多 Agent。

管线为显式步进：`parse → validate → (review gate) → commit → report`，每步输入输出均为 pydantic 模型，无自主决策节点。

## 判定依据

1. **任务性质决定形态**：输入为模板化文本、输出为固定结构表行、判定规则（总额/笔数/日期/重复）可枚举 → 典型确定性数据处理，工作流最优。
2. **约束反向选择架构**：题目要求「不猜测」；Agent 的本质能力是自主决策，自主性越强越易猜测。工作流把每步钉死，**天然满足不猜测**。
3. **多 Agent 属过度设计**：单文档、单职责链，无需要并行探索的分支；多 Agent 只增加协调成本与不可控性。

## 对照评估

| 维度 | 单体 Agent | 多 Agent | 普通工作流（选定） |
|---|---|---|---|
| 可复现性 | 低 | 低 | 高 |
| 可解释性 | 低 | 低 | 高 |
| 契合「不猜测」 | 差 | 差 | 好 |
| 离线可跑 | 差 | 差 | 好 |
| 开发成本 | 中 | 高 | 低 |
| 复杂度 | 中 | 高 | 低 |

## 面试答辩口径（一句话）

> 「本题是强规则、强约束、要求『不猜测』的数据处理任务，因此选**确定性工作流**而非 Agent——工作流每一步可复现、可解释、可测试，天然满足不猜测；LLM 只作为**可选的语义交叉校验旁路**，与规则不一致时**升级人工**而非择一，保证无密钥也能完整跑通。」

## Consequences

### 正面
- 每步可日志、可定位到行与规则，异常可追溯。
- 无需 LLM 即可完整演示，答辩不依赖网络与密钥。
- 状态机（`PARSED→…→VERIFIED`）使「人工确认闸门」成为一等公民。

### 负面
- 规则需随文本模板演进而维护（与 ADR-001 R1 同源风险）。
- 工作流的分支需覆盖 P0/P1/P2 全部分级，编排代码需细心组织（以单文件 ≤300 行约束拆分）。
