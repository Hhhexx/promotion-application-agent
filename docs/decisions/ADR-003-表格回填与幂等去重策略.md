# ADR-003：表格回填与幂等去重策略

## Status

Accepted（Phase 1）

## Background

题目要求「将信息写入《推广账号表》的测试副本」，并在发现重复申请时标记提醒而非自动处理。物料 C 的账号表含 13 字段、16 行，存在空行、空抖音号、重复博主（葵花夫妇 2 行）、日期格式混杂等问题。需要明确：**哪些字段可回填、哪些必须人工、哪些禁止覆盖**，以及**去重与幂等的复合键**与归一化步骤。

关键语义约束（来自物料字段说明）：**「报价」是博主合作报价，「抖加」是抖加流量券费用，二者是不同概念**，绝不可混淆。

## Decision

### 1. 字段回填权限（分级）

| 级别 | 字段 | 规则 |
|---|---|---|
| 可回填（需过闸门） | 抖加、抖加支付人 | 来自抖加申请；已有非空值不覆盖（P1） |
| 人工确认后才可写 | 是否打款、打款人、打款日期 | 需存在人工裁决记录（`accept`/`override`）且无未裁决 P0 |
| 系统可写 | 备注 | 写入审计：来源、request_id、确认人、时间 |
| 禁止自动写/改 | 类型、抖音昵称、抖音号、报价、发布日期、是否接单、审核结果 | 文本无来源或不属自动范畴；`quote_price` 设为只读语义，写入即抛错 |

### 2. 抖加金额 ≠ 报价（硬约束）

- 「报价」列**只读**，任何写入路径直接抛错；该错误在测试中必须被覆盖。
- 抖加金额只允许写入「抖加」列。

### 3. 去重与幂等复合键

```
dedup_key = f"{biz_type}|{request_date_iso}|{blogger_name_norm}|{amount:0.2f}|{payer_norm}"
```

示例：`advance|2026-09-03|葵花夫妇|500.00|林老师`

### 4. 归一化步骤（确定性，可单测）

1. Unicode NFKC（全角→半角，符号语义统一）。
2. 去除零宽字符与控制字符。
3. 折叠连续空白为单空格并去首尾。
4. ASCII 段转小写，CJK 段保持不变（不做拼音/简繁转换——属猜测）。
5. 金额去 `¥` 与千分位，`Decimal` 量化 2 位。
6. 日期归一并补全两位数年份（确定性规则，记录审计）。

**禁止的"归一"**：去昵称装饰后缀（`（虾仁）`）、去前缀 `@@`、同义昵称合并。

### 5. 幂等语义

- 同请求内 `dedup_key` 冲突 → `DUPLICATE_WITHIN_REQUEST`（P0，重复申请）。
- 已写入测试副本的 `dedup_key` 再次提交 → `SKIPPED_ALREADY_WRITTEN`（幂等，不重复写、不报错）。

### 6. 匹配策略（候选 + 升级，禁止猜测）

`EXACT_ID` / `EXACT_NAME`（唯一命中）→ 可自动回填；`AMBIGUOUS`（≥2 行，如葵花夫妇）→ P0 人工选行；`NO_MATCH` → P0 人工处理，**禁止自动新建行**；`WEAK_FUZZY` → 仅候选提示，不自动采用。

### 7. 写入策略与演示态存储（Phase 1 定档）

**写入策略：追加 + 溯源列（不覆盖）。** 原表只读，副本保留每次写入轨迹；覆盖会破坏可追溯性。溯源列以**下划线前缀**标识系统列（`_batch_id / _request_id / _rule_id / _confirmed_by / _confirmed_at / _dedup_key`），与业务 13 列并存、不污染业务字段。源表只读，副本复制后再写。

**演示态存储：内存为主 + 裁决日志落 JSONL。** 主数据（请求、解析结果、裁决）驻内存，演示够用且零外部依赖；**裁决日志 append-only 落 JSONL**，使重启后仍可回放裁决轨迹（审计与演示均受益）。不引入 SQLite；若后续 QA 需跨重启保留主数据，再评估升级。

以上两项均登记于 `docs/decisions/OPEN-DECISIONS.md` 关闭记录。

## Consequences

### 正面
- 回填权限分级使「不猜测」在字段级可执行、可测试。
- 幂等键保证重复提交安全，账号表不产生重复行。
- 只读报价字段从根本上杜绝「抖加误入报价」的语义错误。

### 负面
- 组合键包含 payer，若同一博主同日同额不同支付人会被视为不同条目（符合语义，但需在文档说明）。
- 昵称归一不做语义合并，可能出现"看起来同一个人却是两条"的情形——这是**有意为之**（避免猜测），代价是更多人工确认。

### 风险与缓解
| 风险 | 缓解 |
|---|---|
| 归一化写错导致重复未被识别（静默错误） | 对幂等键大小写/全半角做变异定向用例 |
| 日期补全规则歧义 | 规则确定且写审计；无法唯一确定 → `DATE_UNRESOLVABLE`(P0) |
| 覆盖既有非空人工字段 | 写前非空检测，不覆盖，转 P1 提示 |
